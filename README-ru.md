# Vibe Atlas

[![CI](https://github.com/WarLikeLaux/vibe-atlas/actions/workflows/pages.yml/badge.svg?branch=main)](https://github.com/WarLikeLaux/vibe-atlas/actions/workflows/pages.yml)

[English](README.md) | Русский

Vibe Atlas собирает бенчмарки coding agents и моделей, рекомендации вендоров и опыт разработчиков и вайбкодеров. У каждого опубликованного результата будут источник, дата проверки и точные сведения об агенте, модели и условиях измерения.

Сначала собираем бенчмарки и рекомендации. Информация о подписках будет справочной: доступные модели, планы и лимиты рядом с результатами и рекомендациями. Выбор под задачу и интеграция с HAPI появятся позже.

## Текущее состояние

Есть каркас на React и TypeScript, реестр источников с поиском, проверки качества и публикация на GitHub Pages. Первый импорт Artificial Analysis Coding Agents содержит 37 конфигураций и 111 результатов компонентов, проверенные 10 октября 2026. На сайте доступны поиск, сортировка, условия запусков, паспорта и статусы разбора. Раздел моделей AA добавляет 697 конфигураций, проверенных в тот же день, и сохраняет полный исходный набор. [Общая таблица моделей](docs/model-comparison.md) показывает выбранные версии, диапазоны конфигураций, сортировку по бенчмаркам и медали. Первые десять строк дополняются по клику; полная сверка актуальности редакционного набора ещё не завершена. Подробнее: [импорт моделей](docs/aa-models-import.md). Оставшиеся разделы AA, проверенное сопоставление моделей, сведения о подписках и рекомендации ещё предстоят. Подробности: [импорт](docs/artificial-analysis-import.md). [Импорт Cursor](docs/cursor-import.md) добавляет 68 конфигураций CursorBench 4.0 и 14 результатов страницы Composer с отдельными версиями, точной телеметрией и атрибуцией.

Интерфейс и продуктовая документация пока на русском. Оба README описывают одинаковые границы проекта и команды разработки.

Выбранные пользователем модели составляют основной набор. Дополнительный охват включает последние версии конкретных линеек и вариантов вендора. Согласованные различия моделей, версий, агентов и effort описаны в [охвате моделей](docs/model-scope.md). Для нового диалога сохранён [контекст продолжения](docs/handoff.md).

[Официальный Terminal-Bench 4.0](docs/terminal-bench-import.md) добавляет 35 запусков и пять протоколов по агентам. Новые бенчмарки подключаются через общий пакет, без изменения таблицы вручную. Каждая сборка создаёт автономный `dist/vibe-atlas.html`; команды обновления и ограничения описаны в [автоматизации](docs/benchmark-automation.md).

## Приоритеты

1. Собрать широкий реестр релевантных бенчмарков для разработки и импортировать результаты, начиная с [Artificial Analysis Coding Agents](https://artificialanalysis.ai/agents/coding-agents). Сохранять методологию каждого бенчмарка и точную конфигурацию запуска.
2. Собрать рекомендации вендоров, независимые оценки и опыт разработчиков и вайбкодеров. Сохранять авторство, даты, контекст задачи и коммерческие связи.
3. Добавить справочные сведения о планах подписки, доступных моделях, совместимости, цене и лимитах в исходных единицах.
4. Использовать собранные основания для рекомендаций под задачу и будущего версионированного экспорта для HAPI.

## Запуск

Нужен Node.js 22.12 или новее. В CI используется Node.js 22.

```sh
npm ci
npm run dev
```

Vite выведет локальный адрес с префиксом `/vibe-atlas/`.

```sh
npm run check
npm run preview
```

`check` проверяет типы, данные, код, стили, документы, форматирование и неиспользуемый код, затем собирает сайт. `preview` запускает собранную версию из `dist/`. Husky выполняет `check` перед каждым коммитом.

## Проверки

| Команда                    | Что проверяет                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run typecheck`        | TypeScript strict, необработанные индексы, точные optional-поля, неиспользуемые переменные                                            |
| `npm run validate:data`    | Структура реестра источников через Zod                                                                                                |
| `npm run lint:code`        | ESLint, typescript-eslint strict со знанием типов, React Hooks, React Refresh, JSX accessibility, imports, Security, SonarJS, Unicorn |
| `npm run lint:styles`      | Stylelint standard                                                                                                                    |
| `npm run lint:docs`        | markdownlint-cli2                                                                                                                     |
| `npm run format:check`     | Prettier                                                                                                                              |
| `npm run check:unused`     | Knip                                                                                                                                  |
| `npm run build`            | Проверка TypeScript и production-сборка Vite                                                                                          |
| `npm run audit:production` | Уязвимости зависимостей сайта                                                                                                         |

Для форматирования: `npm run format`. ESLint работает с нулевым допуском к предупреждениям. Локальное исправление стилей: `npx stylelint 'src/**/*.css' --fix`.

`npm run audit:production` проверяет зависимости сайта и выполняется в CI. Полный `npm audit` на 10 октября 2026 сообщает о восьми связанных high findings в инструментах разработки из-за `braces@3.0.3` ([advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)). Исправленной версии `braces` в npm на эту дату нет. Шаблоны glob в командах проекта заданы явно, `braces` не входит в клиентские зависимости. Overrides для `smol-toml` и `katex` устраняют отдельные исправленные advisories, обновления отслеживает Dependabot.

ESLint 9 и Unicorn 62 выбраны как совместимый набор с `eslint-plugin-jsx-a11y`, который пока не объявляет поддержку ESLint 10. TypeScript должен оставаться в диапазоне поддержки typescript-eslint, а типы Node должны соответствовать среде Node 22. Обновлять связанные major-версии нужно вместе, без `--force` и `--legacy-peer-deps`.

## Публикация

Публичный репозиторий публикуется бесплатно на GitHub Pages. В Settings → Pages должен быть выбран источник GitHub Actions. Workflow `.github/workflows/pages.yml` выполняет проверки и сборку для pull request, а для `main` дополнительно публикует проверенный артефакт. Pull request не получает права на деплой.

Путь Vite настроен на `/vibe-atlas/`. Сайт использует ссылки на секции, поэтому не требует серверного SPA fallback. Официальные инструкции: [Vite](https://vite.dev/guide/static-deploy.html#github-pages), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages).

## Источники и участие

`data/sources.json` содержит реестр выбранных источников. Новый источник имеет статус `registered` и `lastCheckedAt: null`. Дата регистрации не является датой проверки тарифов или результатов.

Будущий импорт Artificial Analysis должен сохранять исходный снимок, точные названия связок и условия измерений. Секреты импорта остаются в GitHub Actions Secrets. Политика происхождения, свежести и коммерческих ссылок описана в [документе о данных](docs/data-policy.md).

Чтобы предложить бенчмарк, рекомендацию или исправление, [создайте issue](https://github.com/WarLikeLaux/vibe-atlas/issues/new) с исходной ссылкой, автором или издателем, датой публикации при наличии и относящимся к материалу агентом, моделью или задачей. Не добавляйте выдуманные результаты, квоты и отзывы.
