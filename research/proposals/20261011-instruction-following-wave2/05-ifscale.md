## Тест и результаты

- Название и версия: IFScale, протокол статьи arXiv:2507.11538v1. Отдельного semver нет.
- Назначение и тип задач: составление делового отчёта с 10–500 обязательными ключевыми словами. Это узкий тест большого числа одновременных ограничений.
- Метрика, единицы и направление: accuracy по исполнению keyword constraints, проценты, выше лучше. Плотности являются разными условиями.
- Исходное название модели: исторические `o3 (high)`, `gemini-2.5-pro-preview`, `grok-3-beta` и другие строки CSV.
- Соответствие каталогу: актуальные целевые версии в просмотренном наборе отсутствуют. Эти модели остаются историческими примерами протокола, на GPT-6, Gemini 3.8 и Grok 4.7 не переносятся.
- Агент, версия, effort и режим: авторский runner через OpenRouter, default generation parameters, reasoning high где применимо по статье. Для отдельных medium/high конфигураций хранить точный label, универсальное соответствие effort не вводится.
- Результат: при **500 инструкциях** `gemini-2.5-pro-preview` **68.9%**, sample std **2.6%**, `o3 (high)` **62.8%**, std **10.6%**, `grok-3-beta` **61.9%**, std **2.7%**. В JSON все опубликованные плотности и конфигурации OpenAI/Google/xAI из таблицы.
- Число задач, попытки, бюджеты и среда: grid 10–500 с шагом 10, пять seeds. Есть retries для отказов, списков слов и плохой связности. Публичный config содержит max_retries 10, но это не best-of-10. Точный budget каждого исходного замера ещё не проверен.
- Доверительный интервал: не опубликован. Sample std не является CI.
- Машинный набор: [ifscale-results.json](ifscale-results.json), все числовые поля 13 исторических конфигураций и отдельные строки latency для пяти выбранных плотностей.
- Способ извлечения и снимок: прямое чтение CSV без округления, хеши в реестре. Таблица и latency CSV не объединялись: labels preview и latency Gemini в CSV отличаются от статьи. Промышленный адаптер отсутствует.
- Охват: данные исторических моделей только для описания протокола. Полная сетка 50 плотностей и сырые seeds из корневого IFScale_results.csv не перенесены, текущих целевых результатов не найдено в просмотренных оригиналах.

## Разбор доверия

Состояния ниже относятся к указанному замеру и версии. Дата разбора: `2026-10-11T20:40:50+00:00`. «Вывод исследователя» отделяет интерпретацию от сообщения источника.

- Независимость: `unknown`. Авторство Distyl AI подтверждено статьёй, отношения с тестируемыми вендорами не выяснены.
- Утечка и обучение на тесте: `unknown`. Публичный словарь и код доступны, пересечения с обучением не проверены.
- Насыщение: `not-reviewed` для актуальных моделей. Исторические значения при 500 ограничениях не подтверждают различимость текущего каталога.
- Воспроизводимость: `unknown`. Есть код и числовые данные, но сверка версии артефактов неполна. Предварительно выявлены различия latency между CSV и статьёй.
- Сопоставимость: `unknown` между источниками latency. Внутри таблицы сравнение требует одинаковой плотности и учёта пяти seeds. [Методология](https://arxiv.org/html/2507.11538v1) допускает повтор после проверки связности через o4-mini, это не строгий single-shot протокол.

## Проверка и передача

- Сверка по оригиналу: числа, единицы и перечисленные условия сверены `2026-10-11T20:40:50+00:00`. Это чтение публикации, самостоятельный запуск не выполнялся.
- Проверяющая роль: исследователь, проверка первоисточников и подготовка передачи.
- Соответствия моделей: Исторические labels сохранены, API aliases preview и конкретные endpoints не уточнялись по сходству.
- Дубликаты: Сайт, CSV и статья описывают одну цепочку авторского эксперимента. Плотности, effort и среднее не становятся независимыми бенчмарками.
- Ограничения и следующий шаг: Нужны результаты актуальных версий. Перед переносом latency установить ревизию каждого CSV и причину расхождений со статьёй. Нет оснований связывать o3 с Astra или Sol.
