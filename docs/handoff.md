## Цель и приоритеты

Пользователь хочет полноценный сайт, который собирает максимум релевантных бенчмарков coding agents и моделей, рекомендации вендоров и опыт разработчиков и вайбкодеров. Собранные сведения должны быть доступны на самом сайте, с источниками, датами проверки и условиями измерения.

Первый приоритет: бенчмарки и рекомендации. Artificial Analysis Coding Agents выбран первым источником импорта. Охват должен расширяться на другие бенчмарки и рекомендации.

Для каждого бенчмарка требуется описание назначения, требований и методологии, оценка независимости, насыщения, риска утечки, воспроизводимости и сопоставимости. Структура сущностей, карточки и статусов проработана в [методологии бенчмарков](benchmark-methodology.md). Условия теста и конкретного замера различаются, выводы требуют источников и дат. Первый слой машинных схем и интерфейс реализованы для Artificial Analysis; полный редакционный аудит ещё предстоит.

Подписки являются справочным разделом: доступные агенты и модели, планы, лимиты, окна сброса и условия доступа. Исходная потребность связана с использованием уже оплаченных подписок и переключением между инструментами после исчерпания лимита. Цена API не является основной осью выбора.

Покупка, скидки и реферальные ссылки обсуждались как возможное дальнейшее дополнение. Коммерческая связь должна быть явной и не влиять на оценки. Позже HAPI сможет использовать данные сайта для сортировки доступных агентов и моделей по соответствию задаче.

## Важное уточнение об охвате

Начальный основной набор из десяти позиций согласован и сохранён в [охвате моделей](model-scope.md). Он задаёт приоритет сбора данных. В него добавлены GLM-5.3 отдельно от Flash и Grok 4.7 через Cursor Pro. Пользователь уточнил целевую версию Luna как GPT-6.1 Luna. Проверка первоисточников 10 октября 2026 подтверждает GPT-6 Luna, а подтверждение версии 6.1 не найдено. Запрошенная версия помечена как требующая подтверждения, её идентификатор нельзя придумывать или подменять идентификатором GPT-6 Luna. Источники и результаты проверки находятся в документе об охвате. Полный каталог охватывает актуальные версии всех конкретных линеек и значимых вариантов соответствующих вендоров.

Sol, Luna и Astra нужно различать отдельно. Muse Spark 1.3 и Muse Spark 1.3 Contributor, MiniMax M3 и MiniMax M3.1 Flash Preview, GLM 5.3 и GLM 5.3 Flash тоже учитываются отдельно. Это примеры пользователя, точные идентификаторы и актуальность требуют проверки. «Последняя у вендора» и деление по ролям «старшая / быстрая / компактная» не описывают согласованное правило.

Продуктовый список и правила охвата являются публичной документацией. Персональная инвентаризация, локальные настройки и другие приватные сведения остаются вне репозитория.

Effort является настройкой запуска. Для одной модели могут существовать отдельные результаты по агентам, effort и другим условиям. Названия, варианты, версии и конфигурации нельзя терять при сопоставлении.

Бенчмарк может содержать много моделей. Сохраняем исходный снимок, а охват каталога определяем выбранным набором и актуальными версиями конкретных линеек. Обсуждавшаяся идея автоматически делать все модели каждого импортированного бенчмарка полноправными участниками каталога была уточнена пользователем в пользу этого ограниченного охвата.

## Что ещё предстоит

Импорт AA Coding Agents, AA Models, CursorBench 4.0 и таблицы Composer реализован. Исторические статьи и остальные исследования Cursor ещё не разобраны. Полный каталог моделей с подтверждёнными API ID и соответствиями линейкам, оставшиеся разделы AA, каталог рекомендаций и проверенные сведения о подписках ещё предстоят. Исходная таблица AA содержит предыдущие поколения; не помечай её целиком как актуальный каталог моделей.

Следующее направление работы: проверить названия и идентификаторы согласованного основного набора по первоисточникам, оформить машинные записи и соответствия конкретным линейкам и вариантам, затем расширять уже работающий импорт Artificial Analysis на остальные бенчмарки и выполнять редакционный аудит методологий. Явное сопоставление опубликованных названий в редакционном наборе реализовано; полная сверка актуальности и официальных API ID ещё предстоит. Детали универсального сопоставления effort пока открыты. Неизвестные настройки сохраняются явно.

Пользователь разрешил начать реализацию с Artificial Analysis и далее улучшать фреймворк. Текущее состояние коммитов и публикации проверяй в Git; наличие реализации в рабочем дереве не означает её публикацию.

## Команды и правила работы

Для выдачи исследовательских заданий через HAPI прочитай [инструкцию запуска агентов](hapi-agent-launch.md) и [регламент исследования](research-workflow.md). На 11 октября 2026 доступны `list_launch_options` и `launch_agent`, через них запущена [первая партия исследований](../research/README.md) из шести Codex-агентов. Задания доставлены, работа началась, результаты принимаются отдельно по отчётам. Персональные настройки и связи заданий с сессиями хранятся вне репозитория.

```sh
cd vibe-atlas
npm ci
npm run dev
npm run check
npm run audit:production
```

CI использует Node 22, Vite работает с префиксом `/vibe-atlas/`. Husky запускает `check` перед коммитом. Связанные major-версии инструментов нужно обновлять совместно с учётом peer dependencies и среды. Известные findings полного аудита dev-зависимостей описаны в README.

Следуй `AGENTS.md` этого проекта. Для обычных коммитов используется глобальный skill `commit`, merge-коммиты создаёт Git. Публикация уже настроена. Push выполняй только в пределах явно разрешённой текущей задачи. Сохраняй границы конкретной задачи и посторонние изменения.
