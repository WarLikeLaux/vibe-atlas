# Данные и источники

## Происхождение

Опубликованный факт должен ссылаться на источник и содержать дату последней успешной проверки. Дата публикации источника, дата получения и дата проверки различаются. Регистрация URL в реестре не подтверждает содержимое страницы.

Категории доказательств: официальное заявление, независимый бенчмарк, независимый замер и опыт пользователя. В интерфейсе и данных они различаются. Один источник может содержать несколько видов доказательств.

## Единицы и неизвестные значения

Квоты сохраняются в единицах источника: токены, сообщения, запросы, кредиты или бюджет. Диапазон остаётся диапазоном. Качественное описание вроде «больше доступа» не превращается в числовую квоту. Нераскрытый лимит хранится как неизвестный, а не как ноль или безлимит.

Для квоты фиксируются окно, правило сброса, часовой пояс при наличии, общий пул, связанные модели и условия расходования. Если пересчёт единиц является оценкой, сохраняются формула, предположения и основание.

## Точные связки

Вендор, агент, модель, подписка и настройки запуска являются разными сущностями. Для измерения сохраняется полное опубликованное название модели, идентификатор, версия агента при наличии, effort, режим и другие условия. Совпадение краткого названия не означает сопоставимость результатов.

Охват, правила конкретных линеек, вариантов и effort закреплены в [охвате моделей](model-scope.md). Последняя версия определяется внутри каждой конкретной линейки и значимого варианта. Результаты остаются привязаны к точной версии и конфигурации, на новое поколение не переносятся. Неизвестный effort остаётся неизвестным.

## Охват бенчмарков

Первый приоритет сбора данных: бенчмарки и рекомендации по coding agents и моделям. Для каждого бенчмарка сохраняются задача, метрика, направление шкалы, версия, методология и опубликованные ограничения. Результаты разных тестов показываются в своём контексте. Общий рейтинг требует отдельного обоснования, пропущенный результат не считается нулём.

Реестр должен различать найденный источник, проверенную методологию и импортированные результаты. Широкий охват не заменяет проверку происхождения и условий измерения.

## Импорт

Первый запланированный источник: [Artificial Analysis Coding Agents](https://artificialanalysis.ai/agents/coding-agents). Сначала исследуется API или другой доступный формат. HTML-парсер применяется только после проверки структуры и условий использования источника.

Импорт хранит снимок ответа, время, URL, контрольную сумму и версию парсера. Извлечённые данные проходят проверку схемы. Неожиданное исчезновение результатов или полей считается ошибкой импорта. Публикуется только успешный набор, предыдущие результаты сохраняются.

## Свежесть

Частота проверки определяется типом факта и ещё должна быть выбрана. В интерфейсе показывается возраст данных и статус проверки. При сбое обновления дата не продлевается. Изменения цены, лимита, модели и методологии сохраняются в истории.

## Рекомендации

Рекомендация ссылается на основания и описывает подходящий тип задачи. Отзыв сохраняется с автором, датой, контекстом и известной коммерческой связью. Рекомендации разных авторов могут противоречить друг другу, это отражается явно.

Для рекомендаций вендоров и разработчиков сохраняются названные агент и модель, настройки при наличии, условия работы и границы применимости. Субъективный опыт не превращается в числовой результат бенчмарка.

## Коммерческие ссылки

Партнёрская ссылка маркируется рядом с действием покупки. Сохраняются продавец, условия, регион, валюта, срок акции, цена после акции и дата проверки. Комиссия не участвует в оценке качества и порядке рекомендаций.

## Публикация и секреты

Весь набор, попавший в браузер или публичный репозиторий, считается публичным. Токены доступа, идентификаторы пользовательских аккаунтов, приватные логи, остатки персональных квот и платёжные данные не включаются в каталог. Секреты будущего импорта хранятся в GitHub Actions Secrets.
