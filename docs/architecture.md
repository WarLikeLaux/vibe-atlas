# Архитектура

## Текущая версия

React и TypeScript собираются Vite в статический `dist/`. GitHub Actions проверяет проект и публикует артефакт на GitHub Pages. Сайт работает с путём `/vibe-atlas/`, ссылки на разделы используют якоря. Сервер и база данных первой версии не нужны.

```text
data/sources.json + data/artificial-analysis.json → Zod → React → Vite → GitHub Pages
```

- `src/app.tsx`: стартовая страница, поиск и фильтр источников.
- `src/comparison-section.tsx`: общая таблица моделей, выбор бенчмарков, диапазоны, конфигурации, медали и паспорта.
- `data/model-catalog.json`: явный редакционный набор версий и соответствия опубликованным названиям источников.
- `src/data/comparison.ts`: нормализация AA, Cursor и общих пакетов без переноса оценок между поколениями.
- `src/data/comparison-ranking.ts`: места и награды до поиска, фильтров и ограничения строк.
- `scripts/import-cursor.ts`: получение таблиц Cursor и данных графика без выполнения кода источника.
- `scripts/cursor-source.ts`: безопасный разбор литералов JavaScript и сверка с видимыми таблицами.
- `src/data/`: схемы и загрузка источников, результатов и паспортов.
- `scripts/import-artificial-analysis.ts`: получение страницы и обновление статических JSON.
- `scripts/artificial-analysis.ts`: защита от потери результатов coding agents.
- `scripts/import-aa-models.ts`: получение и обновление результатов моделей.
- `scripts/react-flight.ts`: общий разбор данных React Flight.
- `scripts/import-artificial-analysis.test.ts`: проверка реального CLI и сохранения предыдущего набора.
- `src/data/benchmark-pack-schema.ts`: общий контракт столбцов, паспортов и запусков новых источников.
- `data/benchmark-packs.json`: подключённые пакеты; сейчас официальный Terminal-Bench 4.0.
- `data/import-jobs.json`: задания обновления источников.
- `scripts/refresh-benchmarks.ts`: последовательный импорт и полные проверки со сборкой.
- `scripts/standalone-html.ts`: Vite plugin, создающий автономный HTML из того же bundle.
- `scripts/validate-data.ts`: проверка данных перед сборкой.
- `docs/`: план, политика данных и устройство проекта.
- `.github/workflows/pages.yml`: проверки для PR, публикация только из `main`.

## Следующий слой данных

Правила общей таблицы, охвата и наград описаны в [сравнении моделей](model-comparison.md). Полная сверка актуальности линеек и официальных API ID ещё не завершена; редакционный набор нельзя выдавать за подтверждённый каталог всех последних релизов.

Импорт выполняется вне пользовательского браузера. Он получает источник, сохраняет снимок, извлекает записи и валидирует их. После успешной проверки статические JSON публикуются вместе с сайтом. Фоновый workflow и расписание добавляются после появления рабочего адаптера.

```text
Источник → снимок → адаптер → проверка → публичный JSON → сайт
```

Первый слой каталога: `Vendor`, `Agent`, `Model`, `RunConfiguration`, `Benchmark`, `BenchmarkResult`, `Recommendation`, `Evidence`. Он описывает результаты, методологии и рекомендации с контекстом задачи. `SubscriptionPlan` и `QuotaPool` дополняют его сведениями о доступе. `PurchaseOffer` может появиться позже. Идентификаторы и схемы будут определены при первой реализации каталога, это перечень границ, а не готовый API.

Бенчмарк дополнительно разделяется на `BenchmarkVersion`, `Metric`, `EvaluationProtocol` и `EvaluationRun`. Авторство и связи организаций описываются через `Organization`, редакционный разбор через `MethodologyReview` и `RiskAssessment`, составные индексы через `CompositeIndexDefinition`. Результат ссылается на конкретный замер и метрику, повторная публикация сохраняет связь с исходным замером. Подробные требования к сущностям и оценке доверия находятся в [структуре бенчмарков](benchmark-methodology.md). Первые схемы реализованы для источников AA и Cursor; универсальные сущности и связи ещё предстоит выделить по мере подключения следующих источников. Текущие границы описаны в [импорте AA](artificial-analysis-import.md) и [импорте Cursor](cursor-import.md).

## Обновление и ошибки

Сбой импорта сохраняет предыдущий успешный набор. Свежесть данных определяется временем успешной проверки факта, а не временем сборки сайта. Публичный набор не содержит секретов. Импорт не обращается к приватным пользовательским подпискам.

## HAPI

Будущий экспорт является отдельным версионированным контрактом. Vibe Atlas сообщает общие условия и основания выбора. HAPI сопоставляет их с установленными агентами, доступными моделями и персональным состоянием квот. Работа над этим экспортом не требует изменений HAPI в текущем этапе.

## Проверки

`npm run check` объединяет проверки, используемые локально и в CI. Линтеры не дублируют форматирование Prettier. TypeScript и ESLint проверяют данные о типах, Stylelint проверяет CSS, markdownlint проверяет документы, Knip отслеживает неиспользуемый код. Actions закреплены по commit SHA, deployment job получает отдельные права на Pages.

## Автономный просмотр

Каждая успешная сборка создаёт `dist/vibe-atlas.html` со встроенными данными, кодом и шрифтами. Команда обновления источников и подключение пакетов описаны в [автоматизации](benchmark-automation.md), новый источник — в [импорте Terminal-Bench](terminal-bench-import.md). Методология и соответствия моделей требуют редакционной проверки; таблица не требует ручного переноса чисел.
