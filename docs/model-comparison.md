# Общая таблица и рейтинг моделей

Договорённость с пользователем от 10 октября 2026: все импортированные результаты отображаются в одной таблице моделей. Пользователь выбирает бенчмарки, сортирует по конкретному столбцу и сравнивает достижения. Настройки запуска раскрываются внутри строки модели.

## Строки и охват

`data/model-catalog.json` содержит явный редакционный набор из 35 позиций: 32 выбранные версии и три запрошенные позиции без подтверждённых измерений. Соответствия исходным slug AA, конфигурациям coding agents и названиям Cursor задаются явно. Это сопоставление опубликованных названий, а не подтверждение официальных API ID.

Предыдущие поколения из исходных сравнений не попадают в основную таблицу автоматически. Например, Opus 4.7 не заполняет ячейки Opus 5.5. DeepSeek V4 Flash 0731 не заполняет DeepSeek V4.1 Flash. Flash, Contributor и Preview сохраняются отдельно; результаты смешанных систем с дополнительной моделью не приписываются одиночной модели.

Сверка актуальности всех конкретных линеек по документации вендоров ещё не завершена. Каждая выбранная запись содержит источник опубликованного названия, дату и это ограничение. Не следует объявлять весь редакционный набор проверенным списком последних релизов. GPT-6.1 Luna, MiniMax-M3.1-Flash-Preview и Muse Spark 1.3 Contributor имеют статус `requested-unconfirmed` и не наследуют чужие результаты.

Полные исходные снимки, предыдущие поколения, конфигурации и неизвестные поля сохраняются. Исключение из основной таблицы не удаляет сведения из импорта и JSON-экспорта.

## Столбцы и диапазоны

Один столбец описывает метрику конкретной версии теста. AA Models и AA Coding Agents имеют разные протоколы Terminal-Bench 4.0 и отдельные столбцы. Официальный Terminal-Bench 4.0 идёт одним столбцом: агент указан в каждом запуске, так как каждая модель измерена через свой агент. CursorBench 3.1 и 4.0 тоже не объединяются. Нераскрытая версия остаётся неизвестной.

По умолчанию показаны DeepSWE 1.1, Terminal-Bench 4.0 в coding-протоколе AA, SWE-Atlas-QnA и CursorBench 4.0. Все 33 столбца метрик доступны через выбор бенчмарков с поиском. Составные индексы и дополнительные метрики доступны, но не считаются отдельными бенчмарками для медалей.

Диапазон — минимум и максимум опубликованных конфигураций одной модели внутри одного столбца. Он включает разные effort и раскрытые настройки. Это не доверительный интервал, не оценка статистической погрешности и не усреднение результатов. У единственного результата указана одна конфигурация.

Основной результат для места и сортировки выбирается явно: по умолчанию лучший опубликованный запуск; доступен минимум. Пользователь может назначить точный запуск для отдельной ячейки. Такой выбор помечен и сбрасывается отдельно. Раскрытие показывает все конфигурации, источники, даты, ограничения и доступную телеметрию с единицами. Универсальное соответствие effort между инструментами не вводится.

## Места, медали и охват

Место рассчитывается среди измеренных моделей всего редакционного набора для этого столбца. Поиск, фильтр разработчика и показ первых десяти строк не пересчитывают места. Это собственные места Vibe Atlas, а не перепечатанные позиции исходного рейтинга. Используются точные значения до округления. При равенстве применяется порядок 1, 1, 3.

- Золото: место 1. Серебро: место 2. Бронза: место 3.
- Топ-3 и топ-10 включают первые места. Золото одновременно является количеством попаданий в топ-1.
- На модель приходится максимум одна награда в каждом выбранном столбце. Несколько effort не умножают награды.
- Пропуски и оценочные значения не получают мест и наград. Нулевая измеренная оценка остаётся настоящим результатом.
- При единственной измеренной модели награды не выдаются.
- Медали зависят от выбранных столбцов. Индексы, дополнительные метрики AA-Omniscience и предыдущий CursorBench 3.1 исключены из наград.
- Близость к лидеру считается отдельно от медалей в тех же выбранных столбцах: 95%+ от лучшего измеренного результата и полоса 80–95%. Оценочные значения не участвуют, при нулевом топе полосы не выдаются. Полоса не является медалью и места не меняет.
- Один тест в разных протоколах имеет отдельные столбцы и может дать несколько наград. Интерфейс прямо называет знаменатель числом тестов и протоколов. Это ограничение текущего рейтинга, а не свидетельство независимости измерений.

Рядом показан охват: топ-3 и топ-10 из числа выбранных столбцов, где модель измерена, результат не оценочный и есть как минимум две измеренные модели. У моделей с разным охватом медали имеют разную полноту. Общая сортировка сначала сравнивает золото, затем серебро и бронзу; полное равенство разрешается по названию. Можно отдельно сортировать по топ-3, топ-10 и любому выбранному результату в обоих направлениях. Пропуски всегда идут последними.

Повторная публикация одного замера не должна создавать новую награду. Сейчас известный повтор графика Composer не импортируется повторно, а нормализованный идентификатор запуска учитывается один раз. Универсальная сверка цепочек перепубликации между новыми источниками ещё предстоит; несовпадающие версии и неизвестные протоколы нельзя автоматически считать одним замером.

## Масштабирование и проверки

Первые десять найденных моделей показаны сразу; кнопка добавляет следующую десятку. Фильтрация и сортировка выполняются до ограничения строк. Подробные запуски отрисовываются только после открытия ячейки. Это ограничение DOM, а не загрузка данных по сети: исходные JSON пока входят в статическую сборку.

Расчёт мест и наград находится в `src/data/comparison-ranking.ts`, сопоставление и нормализация в `src/data/comparison.ts`, интерфейс в `src/comparison-section.tsx`. Проверки защищают равные места, нулевые и отсутствующие значения, несколько effort, явный выбор запуска, исключение индексов и одиночных измерений. Перед публикацией обязательны `npm run check` и проверка реальной страницы на desktop, mobile, клавиатурой и с пустым результатом.

Для просмотра изменений предоставляется автономный HTML с работающими фильтрами, диапазонами, конфигурациями и JSON-экспортами.

Новые источники подключаются через общий пакет данных; таблица и автономный HTML генерируются автоматически. Устройство и команды описаны в [автоматизации](benchmark-automation.md).
