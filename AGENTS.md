# AGENTS.md

Vibe Atlas является отдельным статическим React-проектом на GitHub Pages. HAPI не является частью этого репозитория.

## Работа

- Прочитай `PRODUCT.md` и относящиеся к задаче документы в `docs/`. Для продолжения нового диалога используй `docs/handoff.md`, для каталога моделей обязательно прочитай `docs/model-scope.md`, для бенчмарков и оценки доверия прочитай `docs/benchmark-methodology.md`.
- Сохраняй текущие пользовательские изменения. Не выходи за границы задачи.
- Для поиска бенчмарков, разбора методологии и сбора мнений прочитай `docs/research-workflow.md` и используй шаблоны в `docs/templates/`. Исследовательские агенты передают результаты в отдельные папки, общие данные интегрируются после сверки по оригиналу.
- Для запуска и координации исследовательских сессий в HAPI прочитай `docs/hapi-agent-launch.md`. Используй `list_launch_options` для выбора проекта и агента, `launch_agent` для создания сессии с заданием. Повтор запуска использует тот же `requestId` и параметры. Локальные настройки и идентификаторы сессий сохраняй вне репозитория.
- Приоритет сбора: результат в исходных единицах и условия запуска, затем опубликованные стоимость и время, затем доступная телеметрия. Недостающие токены отдельно не ищи без задания на анализ расходов. Полученные поля источника сохраняй.
- Используй TypeScript strict. Не добавляй `any`, подавления ошибок и отключения правил вместо устранения причины.
- У каждого опубликованного факта должны быть источник и дата проверки. Не добавляй выдуманные тарифы, квоты, результаты и отзывы.
- Не подменяй единицы квот и точные идентификаторы моделей.
- Не связывай рейтинг с реферальной комиссией.
- Сохраняй продуктовые договорённости, основной набор моделей и правила охвата в документации репозитория. Основной набор задаёт приоритет сбора, полный каталог охватывает актуальные версии всех конкретных линеек и значимых вариантов соответствующих вендоров. Подробности находятся в `docs/model-scope.md`.
- Секреты, локальные абсолютные пути, имена пользователей ОС, персональная инвентаризация и настройки инструментов не должны попадать в публичные файлы, документацию или историю Git. Используй относительные пути. Приватный контекст сохраняй вне репозитория.

## Проверка

Перед публикацией выполни `npm run check`. Для изменений поведения добавляй проверку реального риска, не тесты, повторяющие реализацию. Для интерфейса проверь реальную страницу на desktop и mobile, клавиатурную навигацию и пустое состояние.

Не отключай hooks и проверки. Перед обычным коммитом используй глобальный skill `commit`, если он доступен. Коммить только файлы задачи. Не выполняй push без разрешения пользователя или запроса, который явно включает публикацию.

## Деплой

GitHub Actions публикует `main` только после успешных проверок. Сохраняй корректный base path `/vibe-atlas/`. Pull request не должен иметь deployment permissions. Не меняй настройки аккаунта или другого репозитория ради деплоя.
